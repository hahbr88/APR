# 지출결의서 자동 작성

카드사에서 내려받은 이용내역을 하나의 형식으로 통합하고, 필요한 거래를 선택해 회사 양식의 지출결의서 XLSX로 만드는 Windows 데스크톱 애플리케이션입니다. 원본 카드 파일은 서버나 디스크에 저장하지 않으며 모든 작업 데이터는 사용자 PC에만 보관합니다.

현재 알파 버전은 삼성카드·신한카드·현대카드의 XLSX 이용내역 양식에 최적화되어 있습니다.

## 주요 흐름

1. 삼성카드·신한카드·현대카드에서 내려받은 XLSX 이용내역을 끌어다 놓습니다.
2. 접수자, 접수일, 신청기간 등 문서 정보를 입력합니다.
3. 취소·중복·파싱 오류를 확인하고 필요한 거래를 선택합니다.
4. 고객사명, 업무구분, 지역구분, 실사용 내역 구분, 상세 사유, 청구금액, 출장 기간을 작성합니다.
5. 선택 건수와 금액 및 템플릿 입력 위치를 확인합니다.
6. 원본 `assets/payment-request-template.xlsx`의 서식과 수식을 유지한 지출결의서를 내려받습니다.

## 포함 기능

- 가맹점명 기반 실사용 내역 구분 추천
- 사용자가 수정한 실사용 내역 구분 기억
- 여러 거래의 공통 항목 일괄 편집
- 단계별 작성 화면과 다중 파일 드래그앤드롭
- 신청기간과 같은 기간 자동 입력, 날짜·카드사·거래 상태·주말 제외 필터
- 선택 건수, 실사용 총액, 청구 총액, 제외 금액 요약
- 지출결의서 시트별 입력 행 미리보기
- 날짜·금액·취소 상태·중복 등 오류 및 경고 별도 표시
- 작성 중인 내역을 초안으로 저장하고 다시 불러오기
- 작업 및 AI 추천 결과 자동 복구
- 저장한 초안 삭제·복구 및 현재 작업 초기화
- 최초 입력한 접수자를 로컬에 기억하고 변경 시 문서별 사용 여부 확인
- 선택적으로 Gemini·Groq 개인 API 키를 연결해 실사용 내역 구분과 상세 사유 추천
- 회사 작성 기준과 구분별 판단 기준을 AI 자동완성 설정에 로컬 저장
- AI 요청을 묶음 단위로 처리하고 완료된 결과부터 저장·재시도
- 근거가 부족한 AI 상세 사유는 확인 필요로 표시하고 결과 화면에서 직접 수정
- 취소 거래는 원승인 거래와 자동 연결하고 두 거래 모두 내보내기 대상에서 제외하며, 연결하지 못한 취소 건은 확인 필요로 표시
- 같은 거래로 추정되는 항목은 중복 경고 표시
- 15건을 초과하면 템플릿에 상세 행을 자동 삽입
- 앱에서 GitHub Issues를 통한 건의 및 버그 제보와 개인정보 제외 진단 정보 복사

## 지원 파일

| 카드사 | 지원 형식 | 처리 방식 |
|---|---|---|
| 삼성카드 | XLSX | 열 이름을 찾아 파싱 |
| 신한카드 | XLSX | 열 이름을 찾아 파싱 |
| 현대카드 | XLSX | 승인일·승인시각 등 전용 열 구조 파싱 |

세 카드사의 현재 내려받기 양식에 최적화되어 있으며 다른 카드사나 임의로 편집한 XLSX는 정식 지원 대상이 아닙니다. 파일명만으로 카드사를 판단하지 않고 내부 열 구조를 우선 확인합니다. 읽을 수 없는 행은 조용히 누락하지 않고 오류 목록에 표시합니다.

## 공통 거래 데이터

- 카드사, 카드번호(마스킹), 거래일시, 가맹점명
- 승인금액, 승인번호, 승인/취소 상태, 취소일
- 일시불/할부, 원본 파일명, 중복 식별값
- 실사용 내역 구분, 고객사명, 업무구분, 지역구분
- 상세 사유, 실사용금액, 청구금액, 지방 출장 기간

## 기본 정책

- `지출결의서`에는 거래의 상세 사유를 구분 항목에 건별로 기록합니다.
- `지출결의서`의 거래는 일자가 최근인 순서부터 기록합니다.
- `경비사용내역서`에서 업무구분이 `링스테크내부`인 거래는 `기타` 소계 아래의 내부 상세 영역에 기록합니다.
- 그 외 거래는 8행부터 기록하고 상세 영역이 부족하면 `기타` 소계 앞에 행을 계속 추가합니다.
- `경비사용내역서`의 일반 거래와 내부 거래는 각 영역 안에서 일자가 최근인 순서부터 기록합니다.
- 실사용금액은 원본 승인금액이며 청구금액은 사용자가 수정할 수 있습니다.
- 취소 거래와 파싱 오류 거래는 내보내기 대상에서 제외합니다.
- 중복 의심 거래는 경고 후 사용자가 최종 선택합니다.
- 15건을 초과하면 기존 행의 스타일·병합 구조를 복제해 한 문서 안에서 상세 행을 늘립니다.
- 합계는 프로그램에서 계산하며 Excel에서도 다시 계산하도록 설정합니다.
- 원본 카드 파일은 디스크에 저장하지 않습니다. 초안에는 정규화된 거래와 작성 정보만 저장합니다.

## AI 자동완성

AI 자동완성은 선택 기능이며 사용하려는 사람이 발급받은 개인 API 키가 필요합니다.

### API 키 발급

#### Groq API 키 — 권장

1. [GroqCloud API Keys](https://console.groq.com/keys)에 접속해 로그인합니다.
2. 사용할 프로젝트를 선택하거나 새 프로젝트를 만듭니다.
3. `Create API Key`를 누르고 식별하기 쉬운 이름을 입력합니다.
4. 생성 직후 표시되는 API 키를 복사합니다.

키는 생성 직후에만 전체 값이 표시될 수 있으므로 안전한 곳에 잠시 보관합니다. 모델별 무료 사용량과 요청 제한은 계정 및 Groq 정책에 따라 달라질 수 있습니다. 자세한 절차는 [Groq 공식 Quickstart](https://console.groq.com/docs/quickstart)를 참고하세요.

#### Gemini API 키

1. [Google AI Studio API Keys](https://aistudio.google.com/api-keys)에 접속해 Google 계정으로 로그인합니다.
2. 약관에 동의하고 사용할 Google Cloud 프로젝트를 선택하거나 새 프로젝트를 만듭니다.
3. `Create API key`를 눌러 키를 생성합니다.
4. 생성된 API 키를 복사합니다.

새 사용자는 Google AI Studio에서 기본 프로젝트와 키가 자동 생성될 수 있습니다. 무료 사용량을 초과하면 요청 제한 또는 결제 설정이 필요할 수 있습니다. 자세한 내용은 [Gemini 공식 API 키 안내](https://ai.google.dev/gemini-api/docs/api-key)를 참고하세요.

발급한 키는 다른 사람에게 전달하거나 Git 저장소, 문서, 화면 캡처에 포함하지 마세요. 키가 노출되었다면 해당 공급자 콘솔에서 즉시 폐기하고 새로 발급해야 합니다.

### 앱에서 AI 사용 설정

1. 거래 편집 단계에서 `AI 설정`을 엽니다.
2. `AI 자동완성 사용`을 선택합니다.
3. 공급자로 `Groq (권장)` 또는 `Gemini`를 선택합니다.
4. 사용할 모델을 선택하고 발급받은 개인 API 키를 입력합니다.
5. `연결 테스트`를 눌러 키와 모델이 정상적으로 동작하는지 확인합니다.
6. 연결 성공 후 활성화된 `설정 저장`을 누릅니다.
7. 거래 편집 표에서 분석할 거래를 하나 이상 선택하고 `AI 자동완성`을 실행합니다.
8. 처리 결과에서 추천 구분과 상세 사유를 확인합니다. `상세 사유 확인 필요` 항목은 연필 버튼으로 실제 사용 내역에 맞게 수정합니다.
9. 적용할 항목만 체크한 뒤 `선택 추천 적용`을 누릅니다.

AI 요청이 사용량 제한이나 일시적인 서비스 오류로 중단되면 완료된 결과는 현재 작업에 보관됩니다. `나머지 이어서 재시도`를 누르면 처리되지 않은 거래부터 다시 요청합니다. 같은 결과를 다시 확인할 때는 `AI 결과 보기`를 사용하며, `다시 분석`은 API 사용량이 새로 발생할 수 있습니다.

AI에는 가맹점명, 거래 일시, 금액, 할부 정보, 현재 구분, 업무·지역 정보만 전달합니다. 카드번호, 승인번호, 접수자, 원본 파일명과 API 키는 프롬프트에 포함하지 않습니다. API 키는 Electron의 운영체제 암호화 기능으로 로컬에 저장합니다.

AI는 가맹점만으로 알 수 없는 구체적인 구매 품목이나 사용 목적을 추측하지 않도록 보수적인 공통 사유를 제안합니다. `상세 사유 확인 필요` 항목은 사용자가 실제 사용 내역에 맞게 확인해야 합니다.

## 실행

Node.js 20 이상이 필요합니다.

```bash
pnpm install
pnpm start
```

브라우저 개발 화면은 `http://localhost:3000`에서 확인할 수 있습니다.

개발 중에는 다음 명령을 사용할 수 있습니다.

```bash
pnpm dev
pnpm typecheck
pnpm build
pnpm test
```

`pnpm dev` 실행 시 API는 `http://localhost:3000`, Vite 개발 화면은 `http://localhost:5173`에서 실행됩니다.

## Electron 알파 빌드

Windows x64 데스크톱 앱은 다음 명령으로 실행하고 패키징합니다.

```bash
pnpm electron:dev
pnpm electron:smoke
pnpm electron:dir
pnpm electron:dist
```

- `electron:dev`: 현재 소스를 빌드한 뒤 Electron 창으로 실행합니다.
- `electron:smoke`: Electron 내부 서버, 화면 진입점 및 템플릿 접근을 자동 확인합니다.
- `electron:dir`: `release/win-unpacked`에 설치 없는 테스트 패키지를 만듭니다.
- `electron:dist`: `release`에 Portable 실행 파일과 NSIS 설치 파일을 만듭니다.

Electron에서는 충돌을 피하기 위해 `127.0.0.1`의 임의 포트를 사용합니다. Windows 앱 아이콘은 실행 파일과 설치 프로그램에 적용되어 있습니다. 알파 빌드는 아직 코드 서명이 없어 다른 PC에서 Windows SmartScreen의 `알 수 없는 게시자` 경고가 나타날 수 있습니다.

### 로컬 데이터

초안, 자동 복구, 접수자, 가맹점 분류와 AI 설정은 설치 폴더가 아닌 Electron `userData/data`에 저장되므로 업데이트하거나 재설치해도 유지됩니다. 개발판과 배포판은 서로 다른 경로를 사용합니다.

```text
Electron 개발판: %APPDATA%\지출결의서 작성-dev\data
Portable·설치형: %APPDATA%\지출결의서 작성\data
```

Portable과 설치형은 동일한 배포 데이터 경로를 공유합니다.

## 기술 구성

- Node.js 및 Express API
- React 19, Vite 및 TypeScript 프런트엔드
- Tailwind CSS와 shadcn/ui 컴포넌트
- TanStack Table 기반 거래 테이블
- React Hook Form 기반 문서 입력
- 공통 Zod 스키마를 이용한 브라우저·서버 입력 검증
- ExcelJS를 이용한 XLSX 분석 및 템플릿 편집
- pnpm 패키지 및 잠금 파일 관리
- `tsc` 엄격한 타입 검사, `tsx` 개발 실행 및 테스트

프런트엔드 원본은 `client/src`에 있으며 Vite 빌드 결과는 `dist/client`에 생성됩니다. 서버 빌드 결과는 `dist/server.js`와 `dist/src`에 생성됩니다.

## 템플릿 매핑

### 지출결의서

| 템플릿 열 | 입력값 |
|---|---|
| 구분 | 상세 사유 또는 가맹점명 |
| 실사용금액 | 원본 승인금액 |
| 지출결의금액 | 사용자가 확정한 청구금액 |

### 경비사용내역서

| 템플릿 열 | 입력값 |
|---|---|
| 고객사명 | 사용자 입력 |
| 업무구분 | 프로젝트/유지보수/링스테크내부/기타 |
| 지역구분 | 서울/지방 |
| 일자 | 카드 거래일 |
| 실사용 내역 구분 | 자동 추천 또는 사용자 선택 |
| 지출 사유 | 상세 사유 또는 가맹점명 |
| 실사용금액 | 원본 승인금액 |
| 지출금액 | 사용자 확정 금액 |
| 지방 출장 기간 명기 | 사용자 입력 |

`AI영수증` 시트는 현재 원본 상태로 유지하며 자동 작성 대상에서 제외합니다.
